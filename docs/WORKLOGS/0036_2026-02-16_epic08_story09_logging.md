### Key Changes

1. **Request ID Middleware**
   - Automatically adds X-Request-ID to all HTTP requests/responses
   - Enables end-to-end request tracing
   - Integrates with logrus for structured logging

2. **Error Messages with Hints**
   - Wraps errors with actionable troubleshooting steps
   - Examples:
     ```
     ERROR: audio extraction failed: no audio tracks found
     Troubleshooting:
       - Verify file has audio tracks: ffprobe /path/to/file.mkv
       - Check file is not corrupted
       - Try re-encoding with: ffmpeg -i input.mkv -c copy output.mkv
     ```

3. **Startup Banner**
   - Displays on orchestrator startup
   - Shows version, worker discovery mode, queue size
   - Lists enabled media servers and monitoring status
   - Provides clear visibility into configuration

### Design Decisions

**Decision**: Use middleware for request ID injection  
**Rationale**: Fiber middleware provides clean, reusable pattern for HTTP concerns  
**Trade-offs**: Adds ~0.1ms overhead per request, but provides significant debugging value

**Decision**: Wrap errors instead of replacing them  
**Rationale**: Preserves original error for error.Is() / error.As() checks  
**Trade-offs**: Slightly more verbose, but maintains Go error handling best practices

**Decision**: Use logrus JSON formatter by default  
**Rationale**: JSON logs are easier to parse and aggregate in production  
**Trade-offs**: Less human-readable in terminal, but better for log aggregation tools
